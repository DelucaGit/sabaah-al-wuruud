# Project rules

## Language: everything on GitHub is written in English

The owner uses GitHub as a public portfolio when applying for jobs internationally, so everything that ends up on GitHub must be in English. This applies to:

- Issues, comments and labels
- Pull request titles and descriptions, and review comments
- Commit messages
- Milestone and project (sprint) names and descriptions
- README, docs and code comments
- Branch names

Chat with the owner can stay in Swedish. Only the app's own content (Arabic adhkar, Qur'an text) and quoted source material keep their original language.

## Agile structure

- **Sprint = one release version.** Each version (v1.0, v1.1, v2.0, ...) is a milestone named `vX.Y – Sprint N` with a one-line goal in its description.
- **Epic → user story → task.** Epics carry the `epic` label, user stories `user-story`, tasks `task`. Link them with sub-issues (epic → stories → tasks).
- **User stories** are written as: "As <who>, I want <what>, so that <why>" plus acceptance criteria as a checklist.
- Every new issue gets a type label and a milestone (the sprint it belongs to). Work for a later version goes in that version's milestone, not the current one.
